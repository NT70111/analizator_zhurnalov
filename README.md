# Анализатор журналов

## Возможности

- Читает журнал построчно.
- Проверяет структуру каждой записи, обязательные поля, уровень события и дату.
- Поддерживает фильтры по временному интервалу, уровню и источнику события.
- Выводит сводку в терминал.
- При указании формата и пути сохраняет результат в JSON или CSV.

## Использованные технологии

- JavaScript, Node.js

## Структура проекта

- `main.js` — запускает программу, выводит отчёт в терминал и сохраняет его в файл.
- `parse.js` — разбирает аргументы командной строки, проверяет строки журнала и применяет фильтры.
- `logs/` — папка с файлами журналов.
- `logs/logs_events_sample.log` — пример входного файла журнала.
- `logs/empty_logs.log` — пустой файл для проверки обработки пустого ввода.
- `test/parse.test.js` — автоматические тесты парсера и фильтрации.

## Запуск программы

Откройте терминал в папке проекта и запустите `main.js`. Параметр `--input` обязателен.

### Без фильтров

```powershell
node .\main.js --input .\logs\logs_events_sample.log
```

### Фильтр по уровню

```powershell
node .\main.js --input .\logs\logs_events_sample.log --level ERROR
```

### Фильтры по источнику

```powershell
node .\main.js --input .\logs\logs_events_sample.log --source gateway
```

### Фильтры по временному интервалу

```powershell
node .\main.js --input .\logs\logs_events_sample.log --from 2026-09-27T07:14:01Z --to 2026-09-30T22:55:03Z
```

При одновременном указании нескольких фильтров события на выходе будут соответствоать каждому примененному фильтру.

### Сохранение JSON

```powershell
node .\main.js --input .\logs\logs_events_sample.log --format json --output .\report
```

Программа добавит расширение по формату и сохранит файл как `report.json`.

### Сохранение CSV

```powershell
node .\main.js --input .\logs\logs_events_sample.log --format csv --output .\report
```

Результат будет сохранён как `report.csv`.

Чтобы записать файл, необходимо указать оба параметра — `--format` и `--output`. Допустимы форматы `json` и `csv` (регистр не важен). Если один из этих параметров не указан, программа выводит отчёт только в терминал.

### Подтверждение перезаписи

Если файл с итоговым именем уже существует, программа задаёт вопрос:

```text
rewrite the report.json? (y/yes)
```

Введите `y` или `yes`, чтобы перезаписать файл. Любой другой ответ отменяет запись. В любом случае отчёт перед этим выводится в терминал.

## Вывод в терминале

В терминале отображаются:

- `Valid rows (entire file)` — общее количество валидных строк до применения фильтров.
- `Invalid rows (entire file)` — общее количество невалидных строк в файле.
- `Matched rows` — количество валидных событий, прошедших все заданные фильтры.
- `Invalid rows in entire file (line numbers)` — номера невалидных строк исходного файла; содержимое этих строк не выводится.
- Таблица `Matched events` — события, прошедшие фильтры.

Невалидные строки учитываются независимо от фильтров.

При пустом входном файле программа сообщает об ошибке `file is empty`. Если входной файл не найден или не удалось прочитать/записать файл, ошибка также выводится в терминал.

## Запуск тестов

Тесты написаны на встроенном модуле Node.js `node:test`. Они проверяют разбор строк и аргументов, обработку невалидных данных, фильтры, границы времени, статистику, пустой файл и ошибку при отсутствии файла.

Запуск всех тестов:

```powershell
node .\test\parse.test.js
```

```powershell
node --test .\test\parse.test.js
```
